# 03 - 日志接口详解

> 实测数据来自 10.10.10.11:16601/youlilucky（Lucky 2.26.2）。所有日志接口 GET 分页参数：`pageSize` + `page`。

## 统一结构（绝大多数模块）

```json
{
  "logs": [
    {"LogContent": "...", "LogTime": "2026/08/15 14:53:06", "ShowTime": false}
  ],
  "page": 1, "pageSize": 100, "ret": 0, "total": 11
}
```

- `LogTime` 格式：`YYYY/MM/DD HH:mm:ss`（秒级，本地时区 Asia/Shanghai）
- `page=1` 最新、倒序；翻页直到累计 ≥ `total`
- 无 `logs` 时可能是 `null`（空），`total` 可能反映页大小（需以 `logs` 实际内容为准）

## 系统日志（特殊结构）

```json
GET /api/logs?pageSize=&page=
{"logs": [
  {"timestamp": 1786778546389387303, "log": "configure dir:/app/conf", "time": "2026/08/15 15:22:26"}
], ...}
```

- `timestamp` 为**纳秒级**时间戳（可作增量游标）
- 字段是 `log` / `time`，非 `LogContent` / `LogTime`，需转换

## 按服务日志实测示例

```bash
# 列出服务
GET /api/webservice/rules
# → ruleList: [{RuleKey:"Od3DlnYNbKKrFVmf", RuleName:"Sync", ListenPort:801, EnableTLS:true}, ...]

# 取 Sync 服务运行日志
GET /api/webservice/Od3DlnYNbKKrFVmf/httpserver/logs?pageSize=100&page=1
```

实测：仅 `443` 规则（`JUmyAIaSfMmMI5C7`）有运行日志（TLS 握手错误、SNI 拒绝连接等，共 11 条）；其余服务当前为空。全局 `/api/webservice/logs` 则含所有服务的 `[start][服务名][协议][端口] success` 启动记录。

## 采集增量策略（重要）

由于**无服务端时间过滤**：

1. 首次采集：翻页取全量（pageSize=100，直到 ≥ total）。
2. 增量采集：记录每个「实例+源」的最后游标：
   - 统一日志：最后一条 `LogTime`（秒级）——若存在多同秒日志，用「已见 total」辅助判断。
   - 系统日志：最后一条 `timestamp`（纳秒，精确）。
3. 每次轮询只取最新页（page=1），与本地最新 `LogTime` 比较，把更新的插入。
4. 同秒内多条新日志可能漏取 → 采用「页码差分」：本地存每个源已见 `total` 与最新时间，当远端 `total` 增长时，拉取增量页。

## 访问明细（accessdetail）

```json
GET /api/webservice/{ruleKey}/{subKey}/accessdetail?pageSize=&page=
{"connectiontotal":0,"ipTotal":0,"page":1,"pageSize":10,"resList":null,"ret":0}
```

- 提供连接数 / IP 统计，当前实例数据为空。可作为未来增强数据源。
