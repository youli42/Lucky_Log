# 03 - 日志接口详解

> 实测数据来自 192.168.1.100:16601/youlilucky（Lucky 2.26.2）。所有日志接口 GET 分页参数：`pageSize` + `page`。

## 统一结构（绝大多数模块）

```json
{
  "logs": [
    {"LogContent": "...", "LogTime": "2026/08/15 14:53:06", "ShowTime": false}
  ],
  "page": 1, "pageSize": 100, "ret": 0, "total": 11
}
```

- `LogTime` 格式：`YYYY/MM/DD HH:mm:ss`（秒级，本地时区 Asia/Shanghai）
- `page=1` 最新、倒序；翻页直到累计 ≥ `total`
- 无 `logs` 时可能是 `null`（空），`total` 可能反映页大小（需以 `logs` 实际内容为准）

## 系统日志（特殊结构）

```json
GET /api/logs?pageSize=&page=
{"logs": [
  {"timestamp": 1786778546389387303, "log": "configure dir:/app/conf", "time": "2026/08/15 15:22:26"}
], ...}
```

- `timestamp` 为**纳秒级**时间戳（可作增量游标）
- 字段是 `log` / `time`，非 `LogContent` / `LogTime`，需转换

## 按服务日志实测示例

```bash
# 列出服务
GET /api/webservice/rules
# → ruleList: [{RuleKey:"RULE_KEY_SYNC", RuleName:"Sync", ListenPort:801, EnableTLS:true}, ...]

# 取 Sync 服务运行日志
GET /api/webservice/RULE_KEY_SYNC/httpserver/logs?pageSize=100&page=1
```

实测：仅 `443` 规则（`RULE_KEY_443`）有运行日志（TLS 握手错误、SNI 拒绝连接等，共 11 条）；其余服务当前为空。全局 `/api/webservice/logs` 则含所有服务的 `[start][服务名][协议][端口] success` 启动记录。

## 采集增量策略（重要）

由于**无服务端时间过滤**：

1. 首次采集：翻页取全量（pageSize=100，直到 ≥ total）。
2. 增量采集：记录每个「实例+源」的最后游标：
   - 统一日志：最后一条 `LogTime`（秒级）——若存在多同秒日志，用「已见 total」辅助判断。
   - 系统日志：最后一条 `timestamp`（纳秒，精确）。
3. 每次轮询只取最新页（page=1），与本地最新 `LogTime` 比较，把更新的插入。
4. 同秒内多条新日志可能漏取 → 采用「页码差分」：本地存每个源已见 `total` 与最新时间，当远端 `total` 增长时，拉取增量页。

## 访问明细（accessdetail）— IP 流量/连接统计源

```json
GET /api/webservice/{ruleKey}/{subKey}/accessdetail?pageSize=&page=
{"connectiontotal":2,"ipTotal":2,"page":1,"pageSize":10,"resList":[
  {"IP":"203.0.113.1","IPInfo":"","LastAccess":1786818399,"Connections":1,
   "ConnsStatistics":[{"RemoteAddr":"203.0.113.1:1352","AcceptTime":"2026-08-16 02:26:39","TrafficIn":899,"TrafficOut":89216}],
   "TrafficIn":899,"TrafficOut":89216},
  ...
],"ret":0}
```

- `connectiontotal` = 总连接数，`ipTotal` = 总 IP 数；`resList` 按 `pageSize` 分页，翻到 `ipTotal` 取完。
- 每 IP：`Connections`（连接数）、`TrafficIn/TrafficOut`（入/出流量）、`LastAccess`（最后访问时间戳）。
- **性质：实时快照**（当前连接 / 累计流量），非逐请求历史；与 `access_logs` 的请求计数互补。
- 采集器 30s 节流 UPSERT 入 `ip_traffic` 表，用于 IP 排行的流量/连接展示。

## 子代理层访问日志（Web 访问分析数据源）

`/api/webservice/{ruleKey}/{subKey}/logs` 的子代理层日志 `LogContent` 为**内嵌 JSON**。
Lucky 约 2026-08-16 起变更格式，存在两种结构（解析器 `app/access_parser.py` 向后兼容）：

- 旧版（~2026-08-16 前）：`ExtInfo` 包裹、大写下划线字段

  ```json
  {"LogContent": "{\"ExtInfo\":{\"ClientIP\":\"203.0.113.1\",\"Host\":\"www.example.com\",
    \"Method\":\"GET\",\"URL\":\"/favicon.ico\",
    \"UserAgent\":\"Mozilla/5.0 (Linux; Android 11; V2068A) ... VivoBrowser/30.3.0.0\"},
    \"level\":\"info\",\"msg\":\"fileServer [/favicon.ico]\"}",
   "LogTime": "2026/08/16 03:33:11", "ShowTime": true}
  ```

- 新版（~2026-08-16 后）：扁平、小写、无 `ExtInfo` 包裹

  ```json
  {"LogContent": "{\"client_ip\":\"10.10.10.9\",\"host\":\"10.10.10.2:10002\",
    \"method\":\"GET\",\"url\":\"/api/setup/status\",\"user_agent\":\"\",\"event\":\"[10.10.10.2]\",
    \"level\":\"info\",\"time\":\"2026-08-19 23:00:12\"}",
   "LogTime": "2026/08/19 23:00:12", "ShowTime": true}
  ```

- 旧版字段：`ExtInfo.ClientIP` / `Host` / `Method` / `URL` / `UserAgent`；新版对应 `client_ip` / `host` / `method` / `url` / `user_agent`。
- 解析流程（`app/access_parser.py`）：`LogContent` → JSON → 取 `ExtInfo` 或整对象（扁平）；`UserAgent` 用 `user-agents` 解析出 browser / os / device / device_type（mobile/desktop/tablet/bot）。字段大小写兼容。
- 解析成功写入 `access_logs` 表；非 Web 日志（如规则层 TLS 错误、缺 `client_ip`）仅进 `logs` 表。
- 注意：日志**无 Referer / 状态码**，故"访问来源类型"按设备类型 + Host 域名分组统计。
- 格式切换导致 8/16 起历史访问日志缺失时，可运行 `python -m app.backfill_access` 从 `logs` 表重新解析回填 `access_logs`。
