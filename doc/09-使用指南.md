# 09 - 使用指南

> 面向使用者：从安装、配置到日常操作与问题排查的完整指南。

## 一、项目简介

Lucky Log Viewer 是一个 **Lucky-Admin 日志可视化面板**：通过 Lucky 的管理 API 拉取各模块日志与 Web 访问日志，存到本地 SQLite，在分栏 Web 面板中查看与分析。

- **总览大屏**：KPI（日志总量 / Web 访问 / 活跃服务 / 采集状态）+ 模块分布 / 时间趋势 / Web 访问趋势 / 最近日志实时流。
- **Web 访问分析**：IP 排行、归属地分布、浏览器/OS/设备型号/来源类型/访问路径/趋势，全部图表化；明细支持筛选、详情抽屉、全字段导出。
- **全部历史 IP**：按 IP 去重的全量分页列表，不限于 Top15。
- **实时/手动模式**：WS 推送实时追加，或手动刷新。

## 二、安装与初始化

前置：Python 3.10+（推荐 3.12）、Node.js 18+。

```bash
# 1. 后端依赖
uv venv --python 3.12
uv pip install -r requirements.txt
# 或: python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt

# 2. 前端依赖并构建（产物输出到 static/dist，由后端托管）
cd frontend
npm install
npm run build
cd ..

# 3. 初始化数据库 + 下载 IP 归属地库
.venv\Scripts\python.exe -m app.init_db --geoip
# 生成 data/logs.db 与 data/ip2region.xdb（若网速慢可单独下载 xdb 放入 data/）
```

## 三、配置（config.json）

> 除直接编辑文件外，也可在 **Web 设置界面**（侧边栏「设置」，见下文）配置，保存后写回 config.json 并热生效。

首次启动若不存在会自动生成默认模板。核心字段：

```jsonc
{
  "web": { "host": "0.0.0.0", "port": 8666 },
  "collect_interval": 10,                 // 采集间隔（秒）
  "cleanup": { "enabled": false, "days": 7 },  // 自动清理旧日志
  "instances": [
    {
      "name": "lucky-main",               // 唯一标识
      "host": "192.168.1.100",
      "port": "16601",
      "base": "/youlilucky",              // SafeURL 前缀
      "token": "OpenToken",               // 必填，鉴权用
      "https": true,                      // 自签名证书自动忽略校验
      "enabled": true,
      "modules": ["system","webservice","docker","cron","ddns","ssl",
                  "webterminal","rclone","filebrowser","wol"]
    }
  ]
}
```

- 多实例：`instances` 数组可放多个，前端顶部切换，数据以 `instance` 字段区分。
- `modules` 白名单：可选 `system webservice docker cron ddns ssl webterminal rclone filebrowser wol ftpserver webdav dlnaservice frp cloudflared ipdb storagemanagement thirdPartyAuthManager`；后几项多为空日志。
- **安全**：`config.json` 含 OpenToken，已在 `.gitignore`，**不要提交**。

## 四、启动

### 生产模式（后端托管构建产物）

```bash
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8666
# 浏览器打开 http://127.0.0.1:8666
```

### 开发模式（Vite 热更新）

```bash
# 终端 A：后端
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8666
# 终端 B：Vite（5173，/api /ws 代理到 8666）
cd frontend && npm run dev
# 浏览器打开 http://127.0.0.1:5173
```

启动后采集器自动开始按实例拉取日志；首次全量拉取需一些时间（默认 10s 一轮，多源间 400ms 延迟）。

## 五、界面使用

### 顶栏（全局）
- **实例切换**：多实例时选择数据源。
- **时间范围**：近 1h / 6h / 24h / 7d / 自定义（填起止后点「应用」）。时间筛选对日志与访问分析均生效。
- **实时开关**：开启后订阅 WS，新日志实时插入表格顶部并刷新统计；断线自动重连。
- **手动刷新**：立即重查当前视图最新数据。

### 总览大屏（/overview）
KPI 卡片 + 模块分布 / 日志趋势 / Web 访问趋势 / 服务分布 + 最近日志流。适合"一屏看全局"。

### Web 访问分析（/access，三个 Tab）

**访问分析**
- KPI：总访问 / 独立 IP / 总流量(快照) / 连接数(快照)；连接与流量每 30s 自动刷新，筛选区标注更新时间。
- 图表：访问趋势、地区分布、IP 排行 Top15、浏览器/OS/设备类型分布、设备型号、访问路径、域名、请求方法。
- 下方「全部历史 IP」表：完整 IP 列表（分页、按 IP 筛选），点击行跳到该 IP 的访问明细。
- 筛选：规则 / 子代理 / 域名 / IP 关键词。

**访问明细**
- 按 IP / 路径 / UA 关键词、精确 IP、路径包含筛选。
- 表格默认精简列（时间 | 归属地 | IP | 方法 | 路径 | 客户端 | 流量）：
  - **悬停 IP**：浮层显示完整归属地 + 连接/流量/最后访问。
  - **点击行**：右侧详情抽屉显示完整字段（国家/省/市/ISP、浏览器与 OS 版本、设备品牌型号、原始 UA 可复制）。
  - **⚙ 列设置**：22 个可开关列，选择存 localStorage。
  - **表头排序**：点击列头按该列全量排序（升/降切换）；**每页条数**下拉可调 16~2048 或「全部」；表格无内部滚动条，页面整体滚动。
- 导出 CSV（全字段，含归属地/UA 版本/流量）。

**运行日志**
- 规则层 httpserver 日志（如 TLS 握手错误），`level=rule` 过滤，与访问日志区分。

### SMB 运行状态（/smb，Lucky 3.0.0 新增模块）
- 侧边栏「SMB」进入：状态卡（启用/运行/连接数/会话/在线用户/打开句柄/上下行速率）+ 在线用户列表 + 连接列表（远程地址/会话数，可「断开」）。
- 每 8s 自动刷新；SMB 未启用时显示"未启用"。
- SMB 运行日志与普通模块一样在「模块日志 — smb」查看。

### Docker 面板（/docker）
- 侧边栏「Docker」进入：概览卡（运行/暂停/停止容器、镜像数、Docker/containerd 版本、存储驱动）。
- **本地快照缓存**：Docker 数据存本地 `docker_cache` 表，采集器后台每 60s 预热，进面板**秒显**上次快照（无需等待网络），随后自动刷新。
- **统一自动刷新**：各面板（Docker/SMB/访问分析）共用**设置页的「面板刷新间隔」**（`config.refresh_interval`，0=关闭），无需各自配置；顶部「手动刷新」在实时关闭时可用，点击立即刷新当前视图。
- **切换实例自动刷新**：所有功能视图（总览/访问/模块/Docker/SMB）统一监听实例切换，切换目标服务器时内容自动重载（Docker 同时重置详情抽屉）。
- **容器 Tab**：表格（名称/镜像/状态/CPU%/内存 usage·limit/网络 RX·TX/创建时间，表头点击本地排序）+ 按状态显示控制按钮（停止→开始；运行→停止/重启/暂停；暂停→恢复）+ 点击行 → 详情抽屉（实时资源 + 容器日志 + 进程）。
- **镜像 / 网络 / 卷 Tab**：镜像（标签/大小/架构/被用数）、网络（Driver/子网/网关/连接数）、卷（挂载点/大小）。

### 模块日志（/module/:module，如 System/Docker/Cron/…）
- 通用视图：服务（webservice 时联动规则+子代理）、去重（时间+内容/内容/关闭）、关键词、趋势图、分页、CSV/JSON 导出。

### 设置（/settings）
- **实例列表**：每个实例的名称/地址/协议/启用状态/模块数/采集状态（最近采集、错误、库内条数）；「编辑」「删除」操作。
- **新增/编辑实例**：填写名称、地址、端口、Base 路径、协议（HTTPS/HTTP）、是否启用、OpenToken（可见可编辑）、采集模块复选框。
  - **测试连接**：用当前表单值即时连接目标 `/api/status`，返回成功或具体错误（token 错误会提示 `OpenToken error`），不会保存。
- **手动采集**：每个实例「立即采集」按钮 + 顶部「采集全部」，触发异步采集；正在采集的实例按钮禁用。
- **采集进度**：状态列实时显示 `采集中 · 当前源 · 页 n/m · 已采 N 条`（如 `webservice/80/note`），每 5s 自动刷新；首次全量回填期间可见进度而非干等。
- **本地数据**：设置页「本地数据」卡片显示 SQLite 文件大小、各表行数/估算字节、每实例数据量（日志/访问/流量 IP），每 15s 刷新；总览大屏亦有「本地数据量」KPI。
- **删除实例**：弹窗确认；默认保留其已采集数据（可勾选"同时清除"）。
- **全局设置**：采集间隔（秒，建议 ≥5）、自动清理（开关 + 保留天数）；监听地址/端口只读，改动需重启后端。
- **保存后热生效**：新增实例下一轮即开始采集；地址/Token/协议变化的实例自动重建连接；多实例并发采集（全局 HTTP 并发 ≤2）。
- 改名视为新实例（旧数据按旧名保留）。

## 六、数据概念

| 表 / 数据 | 说明 |
|---|---|
| `logs` | 所有模块的原始日志行（含 Web 子代理层原始日志） |
| `access_logs` | 子代理层**解析后的访问记录**：IP/域名/方法/路径/UA→浏览器/OS/设备 |
| `ip_traffic` | accessdetail **实时快照**：每 IP 连接数/流量入出/最后访问，30s 刷新 |
| 归属地 / UA 版本 | **查询时富化**（ip2region + user-agents），不入库 |

- **访问日志来源**：WebService 子代理层 `/api/webservice/{ruleKey}/{subKey}/logs`，`LogContent` 是内嵌 JSON（含 ClientIP/Host/Method/URL/UserAgent）。
- **连接/流量语义**：accessdetail 快照反映"当前被跟踪的连接与累计流量"，连接稳定时数字基本不变，**不是每秒跳动的实时计数**；前端每 30s 自动刷新。

## 七、常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 新实例一直显示"等待首次采集" | 首次为全量回填较慢属正常；设置页每 5s 轮询会显示`采集中·当前源·页 n/m`。若状态无变化且出现红色错误，多为配置错误（token/地址）或 UA 解析异常（已修复）；可点「立即采集」手动触发。 |
| 明细/总览无数据 | 首次采集未完成，等 10s 轮询跑完；或该实例 token/base 错误（设置页显示"错误:..."）。检查 config.json 或设置界面。 |
| 归属地全是"未知" | `data/ip2region.xdb` 缺失，运行 `python -m app.init_db --geoip`；或 IP 为内网/保留地址（显示"内网/保留"）。 |
| 某模块筛不出日志 | 该模块服务本身为空（如多数 ftp/webdav/frp 为空），或该服务未启用；服务下拉带条数可看是否有数据。 |
| 连接数不变化 | accessdetail 是快照，连接稳定即不变；每 30s 刷新一次，若想看更密可调 `TRAFFIC_INTERVAL`。 |
| 实时模式无推送 | 确认实时开关已开；无新日志时不推送属正常（rclone 等每分钟才一条）。 |
| 页面加载 422/空 | 请用最新构建产物（`frontend` 改动后需 `npm run build`），旧缓存强刷（Ctrl+F5）。 |
| 采集太慢 | 目标对并发敏感，默认节流较保守；可调大 `collect_interval` 或减小 `INTER_SOURCE_DELAY`，但不建议。 |
| 实例一直"退避中/已暂停" | 该实例连续采集失败（网络/鉴权/风控）。前 `max_retries`（默认 3）次指数退避（10/20s…），达到上限后**暂停自动采集**（设置页显示「已暂停 · 连续失败 N 次」）。修复后点「立即采集」手动触发，成功后自动恢复；或保存一次配置也会清除暂停。 |
| 被服务端风控 | 采集失败已改为指数退避 + 连续失败上限后暂停（`backoff.base/max/max_retries` 可在设置界面调整），不再持续重打目标。 |
