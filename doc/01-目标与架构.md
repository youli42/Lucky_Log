# 01 - 目标与架构

## 项目目标

做一个**浏览器后端基于 Web** 的 Lucky-Admin 日志可视化面板，让用户可以非常方便、直观地查看已有 Lucky 实例的日志。

## 核心能力

1. **多实例**：通过配置文件管理多个 Lucky 实例（host / port / token / base），可在前端切换。
2. **全模块日志采集**：拉取 WebService、系统、Docker、Cron、DDNS、SSL、WebTerminal、Rclone、FileBrowser、WOL 等模块的日志。
3. **实时与手动模式**：
   - 实时模式：后台定时轮询 / WebSocket 推送，新日志自动出现。
   - 手动模式：仅点击"手动刷新"时拉取。
   - 两种模式都提供手动刷新按钮。
4. **筛选与检索**：按模块 / 服务 / 时间范围 / 关键词过滤。
5. **自动去重**：默认按「时间 + 内容」去重，可切换为「内容」或关闭。
6. **可视化图表**：模块分布饼图、时间趋势折线、服务分布柱状图。
7. **导出**：CSV / JSON。

## 总体架构

```
浏览器 (static/index.html, 单页 + Chart.js)
   │  HTTP/JSON            (查询 API)
   │  WebSocket            (实时推送, 可选)
   ▼
Python 后端 (FastAPI + uvicorn)
   │  ├── routes/          查询/导出/服务树/统计 API
   │  ├── collector.py     后台采集任务（asyncio）
   │  ├── lucky_client.py  Lucky API 客户端
   │  └── db.py            SQLite 读写
   ▼
SQLite (data/logs.db)
   ▲
采集器定时从各 Lucky 实例拉取日志
   ▼
Lucky Admin API (https://host:port/{base}/api + OpenToken)
```

## 数据流

1. **启动**：读取 `config.json` → 对每个实例初始化服务树（`/api/webservice/rules_lite`）。
2. **采集**：后台任务按实例、按模块轮询日志接口，增量入库 SQLite。
3. **查询**：前端筛选条件 → REST API → SQLite 索引查询 → JSON 返回。
4. **实时**：采集器入库后通过 WebSocket 广播增量，前端实时追加。

## 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.10+ / FastAPI / uvicorn | 异步、类型友好、自带 OpenAPI |
| HTTP 客户端 | httpx | 支持 verify=False、超时、重试 |
| 存储 | SQLite (aiosqlite) | 零运维、单文件、够用 |
| 前端 | 原生 HTML/CSS/JS + Chart.js | 无构建链、易于快速迭代 |
| 配置 | config.json | 多实例、多模块可配 |
