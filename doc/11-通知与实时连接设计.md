# 11 - 通知机制与实时连接设计

> 2026-08-16 · 本轮功能：自动刷新静默化 + 全局通知；时间趋势横轴匹配；实时连接详情（预留拉黑）。

## 一、全局通知机制（前端）

**目标**：自动刷新不再整页重载闪烁，反馈统一走右上角弹窗；机制全局化，所有模块可接入。

### 约定（已写入 AGENTS.md「自动刷新与通知约定」）

- 定时自动刷新一律**静默**：不切换 loading 遮罩、不重建组件，仅替换数据（`ChartBox` 响应式 `chart.update()`）。
- 仅在有意义变化 / 失败 / 手动刷新时通知；自动刷新通知**必须带 `key` + `minInterval` 限频**（默认 30s），禁止逐次弹窗。
- 禁止自造弹窗 / alert。

### 实现

| 文件 | 职责 |
|---|---|
| `frontend/src/notify.js` | `notify({type, title, message, duration, key, minInterval})`；reactive 队列；`dismiss(id)`；同 key 限频 |
| `frontend/src/components/ToastHost.vue` | 右上角堆叠渲染（Teleport to body），四类样式 info/success/warn/error，点击关闭，滑入动画 |
| `frontend/src/App.vue` | 挂载 `<ToastHost />`（全局唯一） |
| `frontend/src/composables/useDataRefresh.js` | 新增 `notifyMessage / notifyKey / notifyMinInterval` 选项：实例切换/手动刷新完成后自动通知 |

### 各视图接入现状

| 视图 | 自动刷新（静默） | 通知触发 |
|---|---|---|
| Access | `silentAutoRefresh()`：静默拉 stats，total 变化 → 通知（30s 限频） | 手动刷新/切换 → 「访问分析已刷新」；错误 → error |
| Docker | `silentAutoRefresh()`：容器数变化 → 通知（30s 限频） | 同上 |
| SMB | `silentAutoRefresh()`：连接数变化 → 通知（30s 限频） | 同上 |
| Overview / ModuleLogs | `useDataRefresh` 静默重载（保留用户主动操作 loading） | 手动刷新/切换 → 「数据已刷新」（10s 限频） |

## 二、时间趋势横轴匹配

**问题**：`timeline` 只返回有数据的桶，切换时间范围后横轴不完整（缺空桶），与所选范围不匹配。

**方案**：`app/db.py` 新增 `_fill_buckets(rows, from_epoch, to_epoch, step)`，`stats_timeline` 与 `access_stats.timeline`
在给定 `from_epoch/to_epoch` 时补齐为连续桶（空桶 count=0）；未给时间范围（全量统计）时原样返回。

**前端**：无需改动，`bucketLabel(bucket)` 直接渲染连续横轴。

## 三、实时连接详情

**问题**：连接数来自采集器 30s 节流快照（`ip_traffic`），不是查看面板时的实时值；且不知道是哪些服务的连接。

**方案**：新增实时接口，点击连接数卡片时即时拉取。

### 接口 `GET /api/access/connections?instance=xxx`

- 遍历实例服务树全部子代理，即时请求 `accessdetail`（pageSize=500 单页）；
- 按服务（规则/子代理）分组返回连接数 / IP 数 / 流量 + 每个访问者 IP 明细（IP、连接数、流量入/出、最后访问、geo 富化）；
- **冷却**：`Collector.live_allowed`（10s/实例）防频繁点击打爆 Lucky；429 时前端展示冷却倒计时；
- **客户端复用**：`Collector.get_client(inst)` 返回缓存客户端（与采集共享全局并发信号量 ≤2，生命周期由采集器管理），404 子代理跳过。

### 前端 `LiveConnections.vue`

- Access 页「连接数」KPI 卡片可点击（`KpiCard` 新增 `clickable`）→ 右侧抽屉；
- 顶部实时汇总（连接数 / 在线 IP / 流量 / 更新时间）+ 手动刷新（冷却提示）；
- 服务分组列表，点击展开该服务 IP 明细表；
- 每行预留「拉黑」按钮（disabled + tooltip「即将推出」）——**一键拉黑为后续功能，接口与 UI 已留位**（后端届时新增 `POST /api/access/block` 之类即可）。

## 四、后续接入指引

- 新模块要自动刷新：定时器回调写**静默**函数（不置 loading），变化才 `notify({ key, minInterval })`；
- 新模块要实时数据：后端复用 `Collector.get_client` + `live_allowed` 节流模式，前端沿用抽屉 + 冷却提示模式；
- 一键拉黑落地时：新增黑名单表 + 采集/展示过滤 + 本接口每行按钮启用，并同步更新本文档与 README。
