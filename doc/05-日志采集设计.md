# 05 - 日志采集设计

## 采集模型

后台 asyncio 任务，按「实例 × 模块源」为采集单元，定时轮询。

### 采集源定义（source）

每个源 = 一个 URL 模板 + 数据转换规则：

```json
{
  "module": "webservice",
  "kind": "by_rule",                 // by_rule: 需遍历规则
  "url": "/api/webservice/{ruleKey}/httpserver/logs",
  "rules": "rules_lite",             // 从服务树获取 ruleKey 列表
  "cursor": "LogTime"                // 游标字段
}
```

内置源（对齐 doc/03）：

| module | 源 | 游标 |
|---|---|---|
| system | `/api/logs` | timestamp(纳秒) |
| webservice | `/api/webservice/logs` | LogTime |
| webservice | `/api/webservice/{ruleKey}/httpserver/logs` | LogTime |
| docker | `/api/docker/logs` | LogTime |
| cron | `/api/cron/logs` | LogTime |
| ddns | `/api/ddns/logs` | LogTime |
| ssl | `/api/ssl/logs` | LogTime |
| webterminal | `/api/webterminal/logs` | LogTime |
| rclone | `/api/rclone/logs` | LogTime |
| filebrowser | `/api/third/filebrowser/logs` | LogTime |
| wol | `/api/wol/logs` | LogTime |

> 其余源（frp/cloudflared/ipdb/storagemanagement 等）多为空，默认关闭或按配置开启。

## 游标与增量

- **统一日志**：游标 = 本地该源最新 `LogTime`（字符串比较可行，格式定长 `YYYY/MM/DD HH:mm:ss`）。
- **系统日志**：游标 = 本地最新 `timestamp`（纳秒整数）。
- **采集动作**：
  1. GET `page=1`（最新页，pageSize=100）
  2. 新日志（时间 > 本地游标）写入；若最新页已全旧，结束
  3. 若最新页存在比游标新的日志，继续翻页直到某页全部 ≤ 游标，或达 `total`
- 辅助：记录已见 `total`，当远端 total 增长而时间未变（同秒多条）时，用「已见总数差」兜底补拉。

## 表结构（SQLite）

```sql
CREATE TABLE IF NOT EXISTS logs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  instance   TEXT NOT NULL,        -- 实例标识（config 中 name）
  module     TEXT NOT NULL,
  rule_key   TEXT,                 -- 服务规则 key（可选）
  rule_name  TEXT,                 -- 服务规则名（可选）
  sub_key    TEXT,
  sub_name   TEXT,
  ts_epoch   INTEGER NOT NULL,     -- 秒级，统一排序用
  ts_text    TEXT NOT NULL,        -- 原始时间字符串
  content    TEXT NOT NULL,
  raw_json   TEXT,                 -- 完整原始行
  fetched_at INTEGER NOT NULL      -- 采集时间（秒）
);
CREATE INDEX IF NOT EXISTS idx_logs_inst_module_ts ON logs(instance, module, ts_epoch);
CREATE INDEX IF NOT EXISTS idx_logs_content ON logs(content);
CREATE UNIQUE INDEX IF NOT EXISTS idx_logs_dedup
  ON logs(instance, module, COALESCE(rule_key,''), COALESCE(sub_key,''), ts_text, content);
```

**去重约束**：入库时以 `(instance, module, rule_key, sub_key, ts_text, content)` 唯一索引 + `INSERT OR IGNORE` 实现（默认去重键「时间+内容」，源码层对空 key 统一存 `''` 以参与去重）。查询期去重键（时间+内容 / 内容 / 关闭）在 `query_logs` 中按参数切换。

**采集游标**：另建 `cursors` 表（PK: instance, module, rule_key, sub_key）存每源 `last_ts`（秒）/ `last_ns`（系统日志纳秒）/ `last_total`（已见远端 total），`last_error` 记录最近采集错误供前端展示。`save_cursor` 用 UPSERT + COALESCE 保证「只记录错误」不会清空已有游标。

> 采集循环采用固定间隔轮询（默认 10s），一轮超时不连续补跑，避免对目标造成持续高负载。

## 节流与容错

- 每实例采集间隔可配（默认 10s）；多源间加小延迟（300-500ms）
- httpx `verify=False`，`timeout=10s`，连接错误重试 2-3 次（退避）
- 单源失败不影响其他源；记录最近错误供前端展示
- 目标对并发敏感：采集并发 ≤ 2

## 失败处理与指数退避（防风控）

> 目标对持续失败请求敏感（会触发服务端风控），故失败必须**上抛**并**指数退避**，而非持续重打。

- **错误分级**：`LuckyClient` 抛出的 `LuckyError` 带 `status`（HTTP 码；网络/业务错误为 None）。`_poll_unified` / `_poll_accessdetail` / `_ensure_tree` 对任何 `LuckyError` 一律**re-raise**（记游标错误后）→ `_collect_instance` 中止 → 实例判失败。此前真实失败被吞掉、`last_error` 常为空且无退避。
- **实例级指数退避**（`_run_instance`）：失败 `fail_count+=1`；
  - `fail_count < max_retries`：`backoff = base × 2^(n-1)`（如 10/20s），±20% 抖动后封顶 `max`；`backoff_until = now + backoff`；`last_error` 记录。
  - `fail_count ≥ max_retries`（默认 3）：**暂停自动采集**（`paused=true`），不再退避重试；`backoff_until=0`。恢复方式：手动「立即采集」成功，或保存配置（`sync_instances` 自动清除暂停）。
  - 成功：`fail_count=0`、清退避、`last_error=None`。
- **循环跳过暂停/退避中实例**：`_collect_once` 只采集未暂停且 `backoff_until <= now` 的实例（零请求）；全部暂停/退避时循环睡到最早可重试时刻，不空转。
- **手动采集不受限制**：`collect_now`/`collect_all` 用户显式触发立即采集，成功即重置退避与暂停。
- 状态字段：`fail_count / backoff_until / next_retry_in / paused` 经 `/api/instances` 透传，设置页显示 `退避中 · 下次 HH:mm:ss` 或 `已暂停 · 连续失败 N 次`。

**配置**（config.json 或设置界面）：
```jsonc
"backoff": { "base": 10, "max": 300, "max_retries": 3 }
```

## 清理策略（可配置）

```json
"cleanup": {"enabled": false, "days": 7}
```

- 默认关闭（不清理）
- 开启后：每轮采集后 `DELETE FROM logs WHERE ts_epoch < now - days*86400`，并 `VACUUM`

## 服务树缓存

- 启动与每 N 分钟刷新 `/api/webservice/rules_lite`，缓存「规则→子代理」树
- 用于：采集 by_rule 源、前端服务导航下拉
- 规则 key 变化时重建游标（视为新规则）

## IP 流量/连接采集（accessdetail → ip_traffic）

对每个有访问日志的子代理，额外轮询 `/api/webservice/{ruleKey}/{subKey}/accessdetail`：

```sql
CREATE TABLE ip_traffic (
  instance   TEXT NOT NULL,
  sub_key    TEXT,
  client_ip  TEXT,
  last_access INTEGER,
  connections INTEGER,
  traffic_in INTEGER,
  traffic_out INTEGER,
  fetched_at INTEGER,
  PRIMARY KEY (instance, sub_key, client_ip)
);
```

- 分页翻到 `ipTotal`，按 `(instance, sub_key, client_ip)` UPSERT。
- **节流**：每源 ≥ 30s 才刷新一次（默认采集间隔 10s，避免对目标产生额外压力）。
- **性质说明**：`accessdetail` 是实时快照（当前连接 / 累计流量），非逐请求历史；前端标注"实时快照，30s 刷新"。
- 展示：IP 排行/详情附 `connections / traffic_in / traffic_out / last_access`，与 `access_logs` 请求计数互补。

## 实时推送

采集器每入库一批日志，即通过内存队列广播给 WebSocket 连接（`/ws/stream`），前端实时模式据此追加。手动模式下前端不订阅或忽略推送。
