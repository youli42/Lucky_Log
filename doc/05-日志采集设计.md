# 05 - 日志采集设计

## 采集模型

后台 asyncio 任务，按「实例 × 模块源」为采集单元，定时轮询。

### 采集源定义（source）

每个源 = 一个 URL 模板 + 数据转换规则：

```json
{
  "module": "webservice",
  "kind": "by_rule",                 // by_rule: 需遍历规则
  "url": "/api/webservice/{ruleKey}/httpserver/logs",
  "rules": "rules_lite",             // 从服务树获取 ruleKey 列表
  "cursor": "LogTime"                // 游标字段
}
```

内置源（对齐 doc/03）：

| module | 源 | 游标 |
|---|---|---|
| system | `/api/logs` | timestamp(纳秒) |
| webservice | `/api/webservice/logs` | LogTime |
| webservice | `/api/webservice/{ruleKey}/httpserver/logs` | LogTime |
| docker | `/api/docker/logs` | LogTime |
| cron | `/api/cron/logs` | LogTime |
| ddns | `/api/ddns/logs` | LogTime |
| ssl | `/api/ssl/logs` | LogTime |
| webterminal | `/api/webterminal/logs` | LogTime |
| rclone | `/api/rclone/logs` | LogTime |
| filebrowser | `/api/third/filebrowser/logs` | LogTime |
| wol | `/api/wol/logs` | LogTime |

> 其余源（frp/cloudflared/ipdb/storagemanagement 等）多为空，默认关闭或按配置开启。

## 游标与增量

- **统一日志**：游标 = 本地该源最新 `LogTime`（字符串比较可行，格式定长 `YYYY/MM/DD HH:mm:ss`）。
- **系统日志**：游标 = 本地最新 `timestamp`（纳秒整数）。
- **采集动作**：
  1. GET `page=1`（最新页，pageSize=100）
  2. 新日志（时间 > 本地游标）写入；若最新页已全旧，结束
  3. 若最新页存在比游标新的日志，继续翻页直到某页全部 ≤ 游标，或达 `total`
- 辅助：记录已见 `total`，当远端 total 增长而时间未变（同秒多条）时，用「已见总数差」兜底补拉。

## 表结构（SQLite）

```sql
CREATE TABLE IF NOT EXISTS logs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  instance   TEXT NOT NULL,        -- 实例标识（config 中 name）
  module     TEXT NOT NULL,
  rule_key   TEXT,                 -- 服务规则 key（可选）
  rule_name  TEXT,                 -- 服务规则名（可选）
  sub_key    TEXT,
  sub_name   TEXT,
  ts_epoch   INTEGER NOT NULL,     -- 秒级，统一排序用
  ts_text    TEXT NOT NULL,        -- 原始时间字符串
  content    TEXT NOT NULL,
  raw_json   TEXT,                 -- 完整原始行
  fetched_at INTEGER NOT NULL      -- 采集时间（秒）
);
CREATE INDEX IF NOT EXISTS idx_logs_inst_module_ts ON logs(instance, module, ts_epoch);
CREATE INDEX IF NOT EXISTS idx_logs_content ON logs(content);
```

**去重约束**：入库时以 `(instance, module, rule_key, ts_text, content)` 判重（唯一索引或查询去重）。默认去重键「时间+内容」；`--no-dedup` 模式不去重入库。

## 节流与容错

- 每实例采集间隔可配（默认 10s）；多源间加小延迟（300-500ms）
- httpx `verify=False`，`timeout=10s`，连接错误重试 2-3 次（退避）
- 单源失败不影响其他源；记录最近错误供前端展示
- 目标对并发敏感：采集并发 ≤ 2

## 清理策略（可配置）

```json
"cleanup": {"enabled": false, "days": 7}
```

- 默认关闭（不清理）
- 开启后：每轮采集后 `DELETE FROM logs WHERE ts_epoch < now - days*86400`，并 `VACUUM`

## 服务树缓存

- 启动与每 N 分钟刷新 `/api/webservice/rules_lite`，缓存「规则→子代理」树
- 用于：采集 by_rule 源、前端服务导航下拉
- 规则 key 变化时重建游标（视为新规则）

## 实时推送

采集器每入库一批日志，即通过内存队列广播给 WebSocket 连接（`/ws/stream`），前端实时模式据此追加。手动模式下前端不订阅或忽略推送。
